## 我们回答了什么

生活中的音乐记录往往是孤立列表：歌名、歌手、次数、最后播放日期。回声群岛把它们转化为可以漫游的地理：同艺人的歌相聚，Live 和录音室版本形成双岛，跨年份艺人连接不同章节。用户再写下自己的记忆，使音乐元数据与人生故事产生由本人解释的新联系。

核心体验：500 首音乐碎片生成二维回声之城与三维音乐群岛；使用者探索最高地标、Radiohead 的时间大桥、97 对 Live 双岛，给熟悉的歌曲留下记忆，最后导出一份可以继续生长的世界备份。

## 相近作品与区别

| 作品 | 相近点 | 本作品的具体区别 |
| --- | --- | --- |
| [Spotify Wrapped](https://support.spotify.com/uk/article/spotify-wrapped/) | 用个人收听数据进行互动叙事与回顾 | 本作品用用户提供的通用五字段 CSV，构建可反复漫游的双视图空间；重点是同艺人、跨年份、不同版本关系，和使用者自己写入的记忆。不是年度播放日志报告。 |
| [Obscurify](https://www.obscurifymusic.com/) | 官方定位为了解音乐品味并与他人比较 | 本作品把注意力放在个人生活碎片的空间联系，不做人与人排名；提供数据依据、笔记与本机备份，用于回忆与表达。 |

我们选择的小切口不是“把全部人生信息塞进 3D”，而是把五个音乐字段完整转化成一个有联系、可探索、可解释和可保存的世界。

## 数据声明

- 源文件为用户提供的 `playlist.csv`：500 条记录，86 位艺人，累计 56,667 次播放，日期覆盖 2019-01-02 至 2024-12-16。
- 这份演示歌单的原始采集过程与真实性未独立核验。没有把它声称为平台官方导出或独立确认的完整听歌历史。
- 几何岛屿、地图布局、章节名称、气候色彩和合成环境音是设计表达。
- 没有生成额外的真实情绪、地理位置、完整年/月播放记录或个人事件；记忆笔记由使用者自己填写。
- 歌曲音频不在数据或交付物中。浏览器可以播放使用者关联的本地音频，或由用户点击查询对应 iTunes Store 曲目短试听；实际商店身份与来源在界面中显示。

## AI 与代码声明

本项目在 2026-10-12 至 2026-10-13 的本次工作中，由用户提出方向，Codex 辅助完成数据检查、方案优化、界面实现、测试与文档。用户提供的 DeepSeek 讨论及文字方案作为设计参考，最终设计经用户选择采用二维 / 三维融合。后续试听初版可由 Git 提交追溯；当前补充了严格匹配、取消、超时、重试与 10 项回归检查。详见 `AI_USAGE.md` 和本地独立 AI 材料包，历史原文按实际记录保留。

默认「本地导览」是确定性规则和字段检索，没有调用语言模型。若使用者配置 API 并主动开启在线 AI，服务端会向所配置的 HTTPS 模型服务发送问题、最多 60 条歌曲元数据和汇总；密钥不进入前端，笔记和音频不发送。在线回复有来源标记，目标受到数据校验，失败时回退本地。未提供 API 密钥，因此交付没有进行真实的付费模型调用。

开源框架为 React、Vite、PixiJS、Three.js 和 Lucide；团队新增内容为数据映射、发现机制、导览与空间叙事、两种渲染器、记忆系统、导出和整体 UI。没有基于现成音乐世界项目换皮。
